# 《谜声档案》游戏策划案

> 基于灵矽语音能力 + 大模型的语音审讯式剧情冒险
> 版本：v1.0 草案 · 2026-10-23

---

## 1. 概述

**一句话定位**：玩家扮演调查员，用语音对 AI 嫌疑人问话，从自由对话中挖出关键证词，找出每章的真凶。

**平台契合点**：灵矽客户端提供实时 ASR 转写与流式 TTS 播放（生产者-消费者音频缓冲），支撑"玩家说 → 角色听 → 角色边想边说"的对话体验；三态机可用于判定玩家发言起止，实现"打断角色发言"的交互。

**目标平台**：PC / 移动浏览器为主；后续可移植至桌面客户端。

**每章时长**：45-60 分钟；一季 5 章 + 终章。

---

## 2. 核心玩法

### 2.1 单章流程

```
读案卷 → 自由询问(3-4名嫌疑人，多轮) → 触发关键证词
      → 出示证据对质 → 锁定真凶 → 检察官终审 → 结局结算
```

### 2.2 核心机制

| 机制 | 规则 | 设计意图 |
|---|---|---|
| **证词触发** | 说出/问到与剧本关键信息匹配的内容时，NPC 说出更深一层秘密，线索册解锁 | 把"问对话"变成可收集进度，避免聊天无目的 |
| **信任度系统** | 威胁、辱骂、频繁打断降低信任度；信任度过低时 NPC 拒绝深谈 | 引导玩家像真正审讯员一样沟通 |
| **证据对质** | 收集齐两条矛盾证词后，可语音指令"出示 XX 证据"发起对质 | 制造推理高潮时刻 |
| **随机真凶** | 每章真凶开局随机，NPC 人设与时间线随之重组 | 提升复玩性；模型不直接知道真凶（见 3.2） |
| **分支结局** | 终章按证据链完整度 + 信任度综合评分 | 3 种基础结局 × 真凶随机组合 |

### 2.3 内容结构

- **每章 = 1 个案件 + 1 名核心嫌疑人 + 2-3 名外围嫌疑人**
- 外围嫌疑人只需人设卡片；核心嫌疑人需要完整时间线脚本
- 章节生产管线：剧本 JSON（真相+人设+线索）→ 注入提示词 → 测试对局 → 发布

## 3. AI 的角色

### 3.1 角色矩阵

| AI 角色 | 职责 | 驱动方式 |
|---|---|---|
| **核心嫌疑人** | 自由对话、按时间线回应、信任度反馈、被对质时反应 | 大模型 + 人设/时间线注入 |
| **外围嫌疑人** | 提供有限证词与不在场证明 | 大模型 + 简化人设 |
| **档案助手** | 结构化提示：当前线索、未询问对象、剩余时间 | 纯程序 UI，不调用模型 |
| **检察官** | 终章质证，按证据链生成不同结局陈词 | 大模型 + 结局模板约束 |

### 3.2 关键设计：模型不掌握真相

- 真凶身份与完整真相**只存在服务端剧本数据**中
- 每轮请求时，按"当前已揭露线索 + 该 NPC 应知视角"动态裁剪注入内容
- NPC 需要说谎时，由程序给出"这句是谎话 + 谎言要点"，模型只负责"说得自然"
- **目的**：玩家无法通过套话让模型"泄露"真凶；更换真凶只需改数据层

### 3.3 上下文工程

每轮请求注入：`人设 + 该视角可知信息 + 已揭露线索 + 最近 8 轮对话 + 信任度状态`。控制 token 成本的同时保持角色一致性。

## 4. 竞品对比

| 维度 | 谜声档案 | 文字冒险（Lifeline 等） | AI 陪聊（Character.AI） | 剧本杀/推理桌游 |
|---|---|---|---|---|
| 交互方式 | 语音自由问话 | 文字选项 | 文字/语音聊天 | 线下/线上语音开本 |
| 剧情结构 | 强结构 + 自由对话 | 纯分支树 | 弱结构 | 强结构 |
| 内容消耗 | 章节制、可追更 | 一次性 | UGC  | 一次性 |
| 推理深度 | 中（证词矛盾设计） | 低-中 | 低 | 高（人际博弈） |
| 社交性 | 弱（可晒成就/讨论） | 弱 | 中 | 强 |
| 硬件门槛 | 麦克风 | 无 | 无 | 需组局 |

**差异化结论**：占位在"强结构剧本"与"自由对话"之间——比文字冒险自由，比 AI 陪聊有目标感；单人不需组局即可获得推理体验。

## 5. 商业价值评估

### 5.1 变现模式

| 模式 | 说明 | 优先级 |
|---|---|---|
| 章节订阅 | 月票解锁新章节，首月免费试玩 | 高 |
| 案件包买断 | 经典案件合集 | 中 |
| 声线/角色 DLC | NPC 专属音色与特别篇 | 中 |
| 语言学习衍生 | 英文案件练口语（附生词提示） | 中（待验证） |

### 5.2 单位经济模型

- 单章推理成本估算：每章约 200-400 轮对话，按当前主流模型定价，成本集中在长上下文轮次
- **关键假设**：月订阅价需覆盖月均章节推理成本 3 倍以上（**待验证**）
- 优化手段：外围 NPC 用小模型；上下文裁剪；NPC 不在场时挂起会话

### 5.3 市场假设

- 参考有声书/播客订阅付费习惯，剧本杀爱好者与悬疑内容消费者是核心人群（**待验证假设**）
- 语言学习场景的付费意愿需单独验证

### 5.4 风险

- 内容消耗型产品，章节生产速度必须匹配订阅节奏——对剧本管线是持续压力
- 模型幻觉导致"NPC 说出矛盾证词"需通过程序层校验兜底
- 一次差评章节对订阅续费伤害大

## 6. 工程考量

### 6.1 对话状态机（防"一句话通关"）

```
服务端权威状态：当前章节 / 信任度表 / 已触发线索 / 对质进度 / 结局分支
模型职责边界  ：只生成台词文本，禁止输出"你已通关"类元话语
```

- 所有进度推进（线索解锁、结局达成）由服务端规则引擎判定，与模型输出解耦
- 模型输出后过一遍"状态一致性校验"：若模型声称给出未触发线索，服务端拦截并重写

### 6.2 语音交互细节

- **打断机制**：玩家发言时（`listen_state=start`）可暂停/跳过当前 TTS 播放，提升对话节奏
- **长回合防冷场**：TTS 流式播放 + "思考中"拟声反馈（如翻纸声）
- **沉默超时**：玩家 20 秒无输入 → 助手主动提示"可以问 XX 的方向"

### 6.3 安全与容错

| 场景 | 策略 |
|---|---|
| 模型超时/限流 | 降级播放预录"沉默反应"，允许切换文字输入，进度保留 |
| 诱导违规内容 | 输入侧敏感词过滤 + 输出侧安全过滤，NPC 被触发时以人设内方式回避 |
| ASR 识别错误 | 关键指令（出示证据、锁定真凶）用按钮二次确认 |
| 长对话上下文丢失 | 每 10 轮做一次摘要压缩注入 |

### 6.4 内容安全（重点）

NPC 会被玩家用语音自由引导，必须：
- 输入输出双通道审核
- NPC 系统提示中内置"拒绝脱离案件话题"约束
- 玩家语音转写文本留存用于举报追溯（合规要求）

### 6.5 里程碑

| 阶段 | 周期 | 产出 |
|---|---|---|
| M1 技术验证 | 2 周 | 1 名 NPC 自由对话 + 线索触发 + TTS，验证上下文方案 |
| M2 单章可玩 | 3 周 | 完整一章：4 嫌疑人 + 信任度 + 对质 + 结局 |
| M3 内容管线 | 3 周 | 章节编辑器/JSON 剧本格式 + 生产流程跑通 |
| 上线 | — | 首季 5 章 + 订阅系统 |

## 7. 待验证假设清单

1. 自由对话中玩家平均多少轮能问出关键证词（影响单章成本）
2. 信任度系统能否真正引导沟通方式，还是被玩家无视
3. 月订阅价对目标人群的转化率
4. 语言学习衍生场景的付费意愿
5. 灵矽 ASR 对审问类长句/方言的识别准确率是否达标
6. 章节生产周期能否压缩到 2 周/章以内
